## v0.23.0 · iPadOS floor, ProRes import, iCloud Drive library

Nothing here was compiled: there is no Swift toolchain in the workspace. Availability was read from Apple's documentation (the JSON behind developer.apple.com/documentation, `metadata.platforms`).

**The floor is iPadOS 16.4** (`ios/project.yml`, three places; there is no MinimumOSVersion in Info.plist, Xcode writes it from the deployment target).
- What sets it: the interface, not the Swift. All video import and playback go through mediabunny on WebKit's `VideoDecoder` (Web Codecs), and the paint core, thumbnails and export draw on 2D `OffscreenCanvas`. Safari 16.4 added "video-only support for Web Codecs" and "2D-only OffscreenCanvas", and Safari 16.4 ships with iPadOS 16.4 (https://developer.apple.com/documentation/safari-release-notes/safari-16_4-release-notes). The CSS uses `@property` (also 16.4) and `color-mix()` (16.2); there is no CSS nesting.
- Swift at the floor, left unguarded: `UIHoverGestureRecognizer.altitudeAngle` and `azimuthAngle(in:)` (16.4), `WKWebView.isInspectable` (16.4, debug builds only), `zOffset` (16.1), `UIPencilPreferredAction.showInkAttributes` (16.0). Everything else is 15.0 or older (`loadTracks`, `load(.formatDescriptions)`, `preferredFrameRateRange`, `UIKeyCommand.inputDelete` 15.0; `UIDocumentPickerViewController(forOpeningContentTypes:asCopy:)` and `UTType` 14.0; `UIKeyCommand.f1` to `f12` 13.4; `MainActor.assumeIsolated` 13.0 by back deployment).
- Guarded with `#available` (the app works without them):
  - iPadOS 17.5: `UIPencilInteraction(delegate:)` (falls back to `UIPencilInteraction()` plus `delegate`), `pencilInteraction(_:didReceiveTap:)` and `didReceiveSqueeze:` with `UIPencilInteraction.Tap`, `.Squeeze`, `.Phase` and `UIPencilHoverPose` (before 17.5 the deprecated `pencilInteractionDidTap(_:)` sends `doubleTap` without a pose; on 17.5 and later it returns at once so nothing fires twice), `preferredSqueezeAction` (sent as "ignore" before), `prefersHoverToolPreview` (left out before, the page reads a missing value as on), `UIPencilPreferredAction.showContextualPalette` and `.runSystemShortcut`, `UITouch.rollAngle`, `UITouch.Properties.roll` and `UIHoverGestureRecognizer.rollAngle` (roll 0 before), `UICanvasFeedbackGenerator` (stored as `UIFeedbackGenerator?`, since a stored property cannot carry `@available`; before 17.5 the canvas kinds play a light impact), `UIImpactFeedbackGenerator(style:view:)` and `impactOccurred(intensity:at:)` (before: `init(style:)` and `impactOccurred(intensity:)`, iOS 13).
  - iPadOS 18.0: `AVVideoCodecType.appleProRes4444XQ`. `proresCodec("4444xq")` returns nil before 18, so the probe skips it and the existing fallback picks ProRes 4444 with its note.
- At runtime, not by guard: on iPadOS 16.4 to 16.x `GpuCompositor.create()` gets no WebGL2 from `OffscreenCanvas` (Safari 17 added "3D OffscreenCanvas WebGL support") and returns null, so the Stage draws with the 2D path.
- Deprecation warnings to expect: `pencilInteractionDidTap(_:)` (deprecated 17.5), `AVAssetExportSession.exportAsynchronously` (deprecated 18.0) and `progress` (deprecated 27.0). Both export calls work on every version; the async `export(to:as:)` was not used because its availability could not be pinned down from the docs.

**Import transcode** (`Engine/TranscodeRoutes.swift`, registered last in `EngineRouter`). Same paths and JSON as `backend/app/routers/transcode.py`: `POST /transcode?kind=&name=` with the file as the body answers `{id, kind, state, progress, error, mime, alpha}`; `GET /transcode/{id}` polls; `GET /transcode/{id}/result` gives the bytes with `mime` as the content type (409 until done); `DELETE /transcode/{id}` cancels and removes; `GET /transcode/capabilities` answers `{ffmpeg: false, heif: false, video: true, engine: "avfoundation"}`.
- Which output: the first video track's format description decides. Alpha is `kCMFormatDescriptionExtension_ContainsAlphaChannel` true or `kCMFormatDescriptionExtension_Depth` 32 (ProRes 4444 with alpha). Alpha and not HEVC: `AVAssetExportPresetHEVCHighestQualityWithAlpha` into MOV, `mime` `video/quicktime`, `alpha` true. Anything else (ProRes 422, ProRes 4444 without alpha, and HEVC, alpha or not, which only arrives here when the window cannot decode HEVC at all): `AVAssetExportPresetHighestQuality` (H.264 and AAC, per Apple's docs) into MP4, `mime` `video/mp4`, `alpha` false. `shouldOptimizeForNetworkUse` puts the index first. Progress is the session's `progress`, capped at 0.99 until done.
- Where: `Caches/Jobs/import-<id>/in.<ext>` and `out.mov|mp4`, the iPad's jobs folder (the desktop uses `<data>/Jobs/import-<id>`). Every poll touches the folder's modified time, because the export builder's orphan sweep removes folders in Caches/Jobs it does not own after 30 minutes without a change. The input is deleted when the export ends; the interface deletes the job after fetching the result; finished jobs are dropped after 30 minutes untouched or past 30 kept, as on the desktop.
- Audio and HEIC answer 503 with a sentence (the interface does not send them on iPad; see below). The body limit is 2 GB because the scheme handler holds the whole request body in memory before the route sees it; the desktop streams up to 8 GB. A file-backed request body is the fix if larger imports matter.
- A background task (no idle-timer change, so a running export keeps the screen awake) covers a conversion while the app goes to the background. Conversions are not queued; each runs its own `AVAssetExportSession`.
- Honest limit: the interface decodes video with Web Codecs, not with a video element. WebKit's video element shows HEVC with alpha, but whether its `VideoDecoder` hands mediabunny frames with alpha is not documented, and WebKit bug 273006 (texImage2D loses alpha from transparent video) suggests frame extraction may drop it. So after a conversion with alpha the interface decodes the first frame and, if every pixel is opaque, the import notice says the clip may play without transparency on this device. A ProRes file the iPad's AVFoundation cannot decode fails with the system's own reason. HEVC with alpha that the window decodes is imported as it is, with no conversion and no check.

Decisions:
- The observer is a `UIGestureRecognizer` subclass that never recognizes: `cancelsTouchesInView`, `delaysTouchesBegan`, `delaysTouchesEnded` false, `allowedTouchTypes` only `.pencil`, `canPrevent` and `canBePrevented(by:)` return false, the delegate answers true to `shouldRecognizeSimultaneouslyWith` and false to both failure requirements. It stays `.possible` while a touch is down and goes `.failed` when every Pencil touch is up and no estimate update is still pending (a one second idle tick forces it).
- One `CADisplayLink` (60 to 120 Hz, created paused) wakes on touch or hover and sleeps after one idle second. Per frame it sends at most one `pencil` and one `hoverPose` message. The link's target is a weak proxy, so it never keeps the controller alive.
- Wire format of `pencil` (payload `k`, `s`, `p`, `u`, all flat number arrays): sample rows of 12 (`id, phase, t, x, y, force/maxForce, altitude, azimuth, roll, estimatedMask, expectingMask, updateIndex`), predicted rows (same stride, only the latest move, `p` present only when it changed, empty on lift), update rows of 7 (`updateIndex, t, force, altitude, azimuth, roll, expectingMask`). `t` is system uptime in ms. Non-finite numbers are zeroed before sending because `JSONSerialization` refuses them.
- Clock: the page sends `pencilClockPing {id}`, the shell answers `pencilClock {id, up}` with `ProcessInfo.systemUptime * 1000`; the page takes the midpoint of the shortest round trip. Native samples carry uptime, the page converts.
- UIPencilInteraction is attached to the web view. Both delegate methods are the 17.5 ones (`didReceiveTap:` with `UIPencilInteraction.Tap`, `didReceiveSqueeze:` with `.Squeeze`); the deprecated `pencilInteractionDidTap` is not implemented. `doubleTap` and `squeeze` carry the hover pose (location, zOffset, altitude, azimuth, roll) when the system has one. The page acts on squeeze `ended` only.
- `pencilPrefs` sends `preferredTapAction`, `preferredSqueezeAction` (names: ignore, switchEraser, switchPrevious, showColorPalette, showInkAttributes, showContextualPalette, runSystemShortcut), `prefersPencilOnlyDrawing`, `prefersHoverToolPreview`. Sent on attach, on `pencilPrefsRequest` and when the app becomes active again.
- Hover: a `UIHoverGestureRecognizer` on the web view, staged and sent once per frame as `hoverPose {state, x, y, z, altitude, azimuth, roll, pencil, t}`. `pencil` is a guess (height above 0 or altitude below straight up) so the page can ignore trackpad hover.
- Haptics: the `haptic` message takes the page's generic kinds (tap, select, snap, success, warning, error) and explicit ones (`alignment`, `pathCompleted`, `impactLight|Medium|Heavy|Soft|Rigid`). `snap` and `alignment` play `UICanvasFeedbackGenerator.alignmentOccurred(at:)`, `pathCompleted` plays `pathCompleted(at:)`, the rest `UIImpactFeedbackGenerator(style:view:).impactOccurred(intensity:at:)`. The point is the page's `x, y` or the last Pencil point. Canvas feedback is felt only on Pencil Pro.
- Limit: `attach(to:)` serves one web view; a second scene's web view detaches the first's recognizers (the page of the first window keeps working, without Pencil extras). A per-scene controller is the fix if multi-window Pencil use matters.
- Not done: `UIPencilInteraction` runSystemShortcut (the page treats it as Off); no `UIPencilInteraction.Squeeze` begin or change actions (only ended).

Decisions:
- **The `.fmo` type.** Exported as `ai.nodemode.formmorpheus.movie`, conforming to `public.data` and `public.content`, extension `fmo`, mime `application/x-formmorpheus` (the desktop association's). NOT `public.zip-archive`, although the file is a zip: that conformance makes Files offer "Uncompress" on a tap and lets archive tools claim it, and it adds nothing the app needs. The type is the most specific one a tap resolves to, so LSHandlerRank Owner gets the file. `CFBundleDocumentTypes` has three entries: the movie (Editor, Owner), the system's picture, video, sound and font types (Viewer, Alternate), and the painting, layered-picture and brush files the interface reads by extension (`.psd .psb .ora .kra .krz .procreate .abr .fvd .fvxproj`, Viewer, Alternate). The third is declared by extension, not by type identifier, so no other company's identifier is spelled in the repository.
- **Opening a movie.** `LSSupportsOpeningDocumentsInPlace` stays true, so the URL is the original. A movie already inside the Library opens by its Library name. A movie from anywhere else (Files, iCloud Drive, AirDrop, Mail) is copied into the Library under a free name ("Name 2", ...) and opens from there; the original is never written. The interface autosaves into the Library, so editing happens on the copy; if the owner later wants true in-place editing it is a bookmark plus a save-back path in the engine, a separate decision. A second tap on the same file reuses the copy when the bytes are identical (`FileManager.contentsEqual`). The copy runs on a background queue, with `NSFileCoordinator` so an iCloud placeholder downloads first, and access to the original is held only while it is copied.
- **Other files** (picture, video, sound, brush, font, layered file) are copied to `<tmp>/Opened/<uuid>/<name>` and sent as `openURL {kind: "import", path, name}`; the page imports them into the open movie (or says to open a movie first). `FilesRoutes` (`GET /files/read`) accepts only `.fmo` paths today: engine builder, it must also serve a file of any extension from `<tmp>/Opened` for this to work (the page calls `api.readFile(path)`). Until then an import from Files shows the engine's refusal as a notice.
- **State restoration.** The page posts `movie {name, id, title}` when the open movie changes. `SceneState` keeps one record per scene (the scene is the one the bridge is talking to, `Bridge.shared.webView?.window?.windowScene`; the message has no scene id), returns `NSUserActivity` type `ai.nodemode.formmorpheus.activity.movie` with `userInfo {name, id}` from `stateRestorationActivity(for:)`, and at the next connect sends `openURL {kind: "restore", name}` unless the launch itself opened a file. - **Keys.** Only combos with the command key (or F1 to F12) are native, so a plain key (Space, a letter, an arrow) is never stolen from a text field; plain-key commands stay in the menus without a shortcut and the page keeps their keys. Once `menuReady` arrives the page swallows the real keydown of exactly those combos (capture listener, only trusted events) and the chosen command comes back as `command {id, source: "native"}`, which the page replays as one synthetic keydown, so Draw & Paint and every dialog see the key as before. - **Edit keys in a text field.** The page tells native when a text field has focus (`menu {kind: "text", focused}`). With it set, native sends the standard edit action (`cut:` `copy:` `paste:` `selectAll:`) down the responder chain to the field instead of the command; undo and redo go to the page, which runs `execCommand`. Edit items stay enabled while a text field has focus.

A movie is never inflated to be copied: poster write and duplicate copy every other entry's compressed bytes as they are (`addRaw`), and only `movie.json` (new id and name on a duplicate) and `poster.png` are written as new stored entries. A session with no lease is gone when its last heartbeat is older than the engine process (the app was quit, killed or reclaimed and started again, so the offer comes at launch) or over 240 s, the desktop fallback. The platform builder should call the lease every 20 s with the heartbeat; without it the heartbeat alone still works.
- Library folder: fixed at `Documents/Library`. `GET /system/library` reports `source: "override"` (the dialog locks as with `FORMMORPHEUS_LIBRARY_DIR`) and `icloud: null`; `POST` answers 409 with a sentence saying the folder is fixed on iPad. The platform builder should hide that setting on iPad.

The export builder's provider (`EngineConfig.capabilityProvider`) merges its fields in. The job targets keep the desktop shape at `GET /api/jobs/capabilities` (export builder).
- Folders by path (Save To, copy-to, `files/read`): only folders inside Documents or a root added to `EngineConfig.extraWritableRoots` or `extraReadableRoots` are allowed. Anything else answers like a system folder on the desktop (400 "That folder belongs to the system. Choose one of your own."; `files/read` answers 403). A path from an older install (old container id) is remapped onto the current Documents. Saving to other places is the native picker's job.
- Brushes: the `PATH_LIMIT` of 240 characters (Windows) is measured on the part below `Documents/Brushes` (200), because the container prefix on iPad is long and not the person's to shorten. The sidecar cache keys on modified time and size like the backend's.
- Guard: a `Host` that is present must be `localhost`; a POST, PUT or DELETE with an `Origin` must carry `fm://localhost` (or `null`, which WebKit writes for an opaque origin). The scheme handler remains the real lock.
- Not ported: `/proxy`, `/transcode` (desktop network and ffmpeg helpers), `/penlink` (hidden on iPad). They answer 404.

## v0.18.0 · ios export

- Files (`ios/Export/`): `JobsRoutes`, `ExportsRoutes`, `AudioEncodeRoutes` (each `init()`, prefixes `/jobs`, `/exports`, `/audio-encode`), `ExportCapabilities`, `ExportJob` (record, registry, sweeps), `AVEncoding` (the encoders), `ExportSupport` (names, folders, exact frame rate, WAV header).
- Capabilities: `ExportCapabilities.dictionary() -> [String: Any]` returns `{ffmpeg: false, avfoundation: true, export: {...jobs capabilities...}}`. `JobsRoutes.init()` installs it through `EngineConfig.capabilityProvider` (chaining any earlier provider), so `/api/capabilities` has it without further wiring. `GET /api/jobs/capabilities` keeps the desktop shape (`targets.h264|hevc|prores|prores4444` with `available`, `encoder`, `reason`, `alpha`, `alpha_reason`, `aac`, `mp3`, `opus`) and adds `engine: "avfoundation"` and per-type `profiles`. Its `ffmpeg` field is true on purpose: `export/route.ts` reads it as "an engine encoder exists"; the platform builder may prefer to test `engine`. `mp3` and `opus` are false.
- What the iPad can encode is not assumed: the first request starts a probe that encodes two 256 x 144 frames with every codec (H.264, HEVC, HEVC with alpha, the six ProRes types) and reports what came out whole. Until it finishes only H.264 and HEVC read as available. ProRes 4444 XQ falls back to 4444 with a note.
- Frames: the interface uploads one PNG per frame (`PUT /jobs/{id}/frames/{n}`, checked by signature), written to `Caches/Jobs/{id}/frames/NNNNNN.png`; the sound is one WAV (`PUT .../audio`). Nothing is decoded until `run`, as on desktop. Each PNG is drawn with CGContext straight into a pooled BGRA `CVPixelBuffer` (premultiplied, sRGB values, `.copy` blend so a recycled buffer needs no clear); the buffers come from the adaptor's pool, so there is no per-frame allocation.
- Timing: the frame rate is the backend's `rate_text` rational (23.976 = 24000/1001, 29.97 = 30000/1001, 59.94 = 60000/1001, else limit_denominator(1000)); frame i is `CMTime(i * den * k, num * k)` with k making the timescale at least 600, and `mediaTimeScale` is set to match. Exactly `frames` frames are appended; the session ends at frames * frame duration. Sound is cut at (frames + 0.5) / fps like the `-t` of the ffmpeg command.
- Colour: output settings carry BT.709 primaries, transfer and matrix, and every pixel buffer is tagged the same, so the conversion to YUV uses the 709 matrix (the ffmpeg path does the same with `scale=out_color_matrix=bt709`).
- Rate control: a bitrate or size target becomes `AVVideoAverageBitRateKey` (size target minus the sound, as `target_bps`). With neither, the quality word sets bits per pixel (low .04, medium .07, high .11, very high .18; HEVC 60 percent of that), because the quality key of the VideoToolbox encoders is not documented for AVAssetWriter. No two-pass: `passes` is always 1. ProRes has no bitrate: the family member nearest below the target is picked as in `prores_plan`, and a note says so.
- Containers: H.264 and HEVC in MP4 or MOV (faststart for both), HEVC with alpha (`hevcWithAlpha`) and every ProRes in MOV only (the job is forced to mov, as the backend forces it for ProRes). Sound: AAC 192 kbps (stereo or mono) or 16 bit linear PCM (MOV only; ProRes always PCM, as the backend).
- Job lifecycle is a port of jobs.py: states queued, receiving, encoding, done, failed, cancelled; `progress()` is received/frames until encoding, then done_frames/frames capped at 0.99; `GET` after done sets `fetched`; at most 40 finished records; abandon sweep every 60 s (10 minutes without upload or poll), orphan folders after 30 minutes, startup sweep after 24 hours; the folder is removed when the encode ends. The finished file goes to Documents/Exports as `{name}.mp4|mov`, never replacing one (`name 2`).
- Background: `run` takes a `beginBackgroundTask` and keeps the screen awake while encoding. If iPadOS ends the extra time the job stops within a frame and fails with a sentence saying so. (iPadOS 26 also has a continued-processing task type for long user-started work; not used because its API could not be verified here.)
- Not done on iPad, and why: chapter markers (the job accepts `chapters` and adds a note that they are not written; AVAssetWriter needs a hand-built timed-text track), two-pass encoding, Opus (no encoder in AVFoundation), MP3 (hidden, owner decision). `POST /audio-encode/mp3` answers 503 like the desktop engine without libmp3lame, and `/lossy` answers 503 for `opus-webm` and `opus-ogg`; `aac-m4a` is encoded with AVAssetWriter into M4A.
- GIF, PNG sequences, APNG, WebP, PSD, TIFF and the other pictures are made inside the interface on desktop too (`GifWriter`, `fflate` zips); the engine's job API never produced them, so no ImageIO code was written. `GET /exports/{name}` returns a memory-mapped `Data` so a large movie is paged, not copied; a file-backed response in `APIResponse` would be better for 1 GB files.
- Temp folder is `Library/Caches/Jobs`, not `Documents/Jobs`: thousands of PNGs would show in Files and go into the device backup. The finished file is in `Documents/Exports`, so it is in Files.
